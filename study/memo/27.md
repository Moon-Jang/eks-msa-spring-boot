스케일 업: 서버 스펙을 올린다.
스케일 아웃: 서버를 증설한다.

보통 스케일 아웃을 선택 이유는 2가지
실제 운영되는 서버를 잠시 멈추고 스펙 업하기 어렵기때문
스펙 업은 비용이 산술급수적으로 오르는게 아니라 기하급수적으로 오를수 있다. 즉 스펙업 비용이 서버 확장하는 비용보다 비쌀 가능성이 있다.

 오토스케일링
 시스템적으로 특정 임계치에 도달했을때 인프라를 확장하는 기능

 pod 오토스케일: 파드의 리소스가 특정 임계치 도달하면 노드에 파드 증설을 요청한다.
 ec2 오토스케일: 노드의 더이상 파드를 늘릴수 없을때 노드를 증설한다.
 - 노드 증설은 k8s 에서 

 HPA: CPU 사용량이나 사용자 정의 파라미터에 기반하여 파드의 수를 자동으로 조정
    - kube-controller-manager 내부의 하나의 루틴(Control Loop)으로 동작합니다.

 적용절차
 - deployment 설정
  - pod 생성/삭제 과정에서 cpu가 튈수도 있으므로 hpa와 resource limit의 체워 여유롭게 세팅
 - 매트릭 서버 설치
  - 지속적으로 파드 리소스 사용량 모니터링하고 hpa에 제공
 - HPA 스크립트 생성 후 적용

minReplica 는 hpa가 우선적용된다.
